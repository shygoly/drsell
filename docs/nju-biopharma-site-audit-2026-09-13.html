三句话结论：① 这批企业 90% 不是 DTC 电商客户，给它们推电商是错配；② 真正的空白在服务层不在交易层——交互模型清一色「400 电话 + 表单 + 微信二维码」；③ Medusa + drsell 的正确定位是「把已经写好但没人读得到的产品知识，变成可自助的售前售后通道」。

§4价值分层

按可兑现程度排序，非按想象力排序。
层级内容可兑现度依赖
L1 售前技术问答把已写好的产品文档灌进 PG，AI 直答「A1800 与 A6000 差别」「有无 FGFR4 品系」「这个砌块的 CAS 与纯度」。替代今天只能打电话这一条路已上线数据摄取（已通）
L2 询报价在线化独立 B2B 询盘（RFQ）模块：身份分流（采购/渠道/机构）× 需求分级（采购/合作/样品/资料/售后）× 线索状态机 new→qualified→quoted→won→closed，带应用场景、预计用量、采购时间线；刻意不含价格（隐藏价 → 询价 → 人工报价）已上线可现场演示
L3 售后自助批号/效期查询、说明书与 SDS 下载、退换货状态；按登录顾客隔离，窥探他人订单被拒已上线并公网复验残留：旧式订单函数仍共享 GRANT
L4 在线交易真正的下单 + 支付（购物车 / 结算 / Stripe / 顾客登录）——唯一真正未实现的一层未实现渠道政策逐家确认是否要做

§5销售话术的事实底座

说法支撑证据
「你的产品文档已经写好了，只是没人读得到。」安图单个产品页含注册证数、通量、温控精度、双备份设计等 10+ 技术维度，足够支撑 20 轮问答——而站点没有任何检索手段
「通用 AI 读不懂你的网站，我能。」实测 0/12 有商品结构化数据、6/12 无 sitemap、金斯瑞直接对机器返 468。drsell 直连 PG，不受 WAF / schema / 爬虫策略影响
「非工作时间你的客户在流失，而且你看不到。」0/12 有在线客服。400 热线 + 表单 = 8 小时外失联、线索散在个人微信、问答数据零沉淀
「AI 说错话的代价，我们用数据库角色锁住了。」adp_reader 零表权限（INV-2）——即使模型被 prompt injection 说服，也只能调 4 个只读函数。对医药行业，「合规可控」比「聪明」重要
